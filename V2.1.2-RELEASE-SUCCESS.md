## 🎓 Lessons Learned

### 1. GitHub Actions Quirks
- YAML document separator (`---`) not supported
- Workflow caching can cause issues (force re-parse with trivial change)
- `softprops/action-gh-release` requires real Git tag (not manual trigger)
- Conditions on jobs need careful testing

### 2. Node/npm in CI
- Always use `npx` for binaries (not in PATH)
- Git hooks (husky) should skip in CI
- Specify Node version explicitly
- Check dependency engine requirements

### 3. Multi-platform Builds
- Linux: Easy (standard runners)
- macOS: Works great on GitHub (free for public repos)
- Windows: Needs Wine or Windows runners
- Python backend: Optional for Electron apps

### 4. Debugging CI/CD
- Read error messages carefully
- Check which workflow is actually running
- Verify file locations (root vs subdirectory)
- Test locally when possible
- Small iterations (one fix at a time)

### 5. Release Process
- Tag pushes are more reliable than manual triggers
- Version consistency checks catch mistakes
- Release notes should be in repo (`RELEASE-NOTES-v*.md`)
- Checksums are important for verification
